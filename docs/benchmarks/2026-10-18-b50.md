These are local, single-user text-inference measurements, not a vendor claim
or an NVIDIA comparison. No RTX 5060 Ti measurements have been made here yet.

## Protocol

39 completed requests: three reload observations, nine unscored warmups, and
27 measured warm requests. Each model received identical user prompt text,
greedy decoding (`temperature=0`), `top_p=1`, seed 42, and one request at a
time. Each of three workloads had one warmup followed by three measured
repeats. The same text tokenizes differently across models.

- Latency: a fixed five-word reply, maximum 32 output tokens.
- Generation: a community-library guide, maximum 256 output tokens.
- Longer input: 80 library records, about 2,300 input tokens, maximum 256 output tokens.

The client ran inside the LXC, avoiding LAN latency. Model/compilation caches
were retained for warm tests. ComfyUI was idle and its models unloaded.
See [exact prompts/settings](2026-10-18-b50-protocol.json) and
[reusable recorder](../../scripts/benchmark_article.py).

To rerun the text benchmark, stop competing GPU workloads and use a fresh output directory:

```bash
ILLAMA_BENCH_URL=http://127.0.0.1:11434 \
  python scripts/benchmark_article.py /path/to/new-benchmark-folder
python scripts/summarize_article_benchmark.py /path/to/new-benchmark-folder
```

If authentication is enabled, export `ILLAMA_API_KEY` privately; it is not
written to the evidence. This detailed recorder expects the documented Linux
container/model layout. Since the October 19 project split, it does not call
another application's API; the operator must stop competing GPU work first.
For a standalone Illama installation, `illama bench` is the general API tool.
The scripts refuse to append new trials to an existing results directory.

## Warm results

Medians of three requests. Output rate is server-retokenized completion tokens
divided by client elapsed time, including prompt processing. First output is
first nonempty streamed API text, not an internal decoder timestamp.

| Model artifact | Short-input output tokens/s | First output, s | Longer-input output tokens/s | Longer-input first output, s | Peak sampled process VRAM, GiB |
|---|---:|---:|---:|---:|---:|
| `gemma-4-E4B-it-int4-ov` | 44.50 | 0.159 | 26.69 | 0.706 | 7.53 |
| `gemma-4-12B-it-qat-int4-ov` | 23.81 | 0.329 | 18.88 | 1.658 | 10.00 |
| `Qwen3.5-9B-ov-awq` | 33.83 | 0.145 | 29.86 | 1.057 | 8.38 |

**Qwen qualification:** the model emits plain-text `Thinking Process:` planning
through the normal content channel and reaches the token cap before answering.
Its rates measure that text, not completed-answer performance. Both Gemma
models produced the requested exact reply in all three short-latency trials;
Qwen did not. This is a formatting check, not an accuracy benchmark.

For short-input generation, sampled card-domain mean power was approximately
68.8 W / 70.0 W / 70.0 W for E4B / 12B / Qwen respectively. These are driver
energy-counter differences over sampled portions of requests, without idle
subtraction. They are not wall-outlet power or complete-request energy.

Full observed ranges, total latency, approximate streaming decode rates,
sampled memory, temperatures, and energy domains are in the
[sanitized results](2026-10-18-b50.json).

## Limits and future comparison

- Retokenized counts and buffered stream chunks are not native decoder counters.
  Approximate decode rates are labeled accordingly; no isolated prefill rate is claimed.
- Three warm repeats are a baseline, not a statistically broad performance study.
- Reload measurements retain disk/compile caches. Gemma was smoke-tested on the
  nightly before this test and Qwen was not; do not compare these as clean cold starts.
- GPU memory and temperatures were sampled; brief peaks can be missed.
- No vision, full-8K-context, concurrent-serving, or model-quality result is claimed.
- An RTX 5060 Ti comparison must identify its exact runtime, weights,
  quantization, CPU, context, cache state, and reasoning settings. Different
  conversions/runtimes compare complete inference stacks, not just GPUs.

Raw streams, telemetry, full private environment details and source snapshots
remain in the operator's private evidence folder. Public data omits LAN
addresses, usernames, host paths, authentication settings and Docker environment.
Model file hashes identify the tested artifacts without redistributing weights.
