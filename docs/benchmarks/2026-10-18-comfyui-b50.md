# ComfyUI on Arc Pro B50 — measurements, October 18, 2026

Configuration and build provenance: [ComfyUI setup guide](../comfyui-b50.md).
The tested runtime is ComfyUI **0.39.0**, PyTorch **2.14.0+xpu**, Intel Omni
**0.2.0-b2**, Kitchen **0.2.37**, AIMDO **0.5.5**, on the **16 GB B50**.
No new models were downloaded. Illama models were unloaded throughout testing.

## Test rules

Single image, batch 1; 512 and 1024 square; the same library-interior prompt.
For each resolution, seed 41 is an unscored warmup, followed by measured seeds
42, 43 and 44. Seeds change to force real denoising rather than return an
entirely cached graph. Model and text-conditioning caches remain warm.

Z-Image uses 8 steps, guidance 1, Euler/simple and AuraFlow shift 3. SDXL
Lightning uses 4 steps, guidance 1 and Euler/sgm_uniform. These are different
model recipes, not equal-step, equal-quality or pure precision comparisons.

Client timings include submission, execution, saving and up to about 250 ms
history polling overhead. Server execution medians are reported separately
in [machine-readable results](2026-10-18-comfyui-b50.json).

## Results with the current memory policy

Warm client medians of three requests; sampled peak process GPU-resident
memory at that resolution. Dynamic VRAM/offload and a 3 GB reserve remain on.

| Existing artifact | 512 seconds/image | 1024 seconds/image | 1024 sampled VRAM, GiB | Verdict |
|---|---:|---:|---:|---|
| Z-Image Turbo FP8 | 5.03 | 15.20 | 13.47 | Runs; representative 1024 output visually checked |
| Z-Image BF16, eight-step test | 3.52 | 14.26 | 13.48 | Executes, but output visibly degraded; not a usable quality baseline |
| SDXL Juggernaut Lightning, four steps | 0.76 | 1.76 | 10.59 | Runs; representative 1024 output visually checked |
| Z-Image INT8 ConvRot | — | — | — | Loader format assertion; VRAM fit not determined |

25 initial jobs were attempted: 24 completed successfully, and the INT8
loader failed before sampling. The INT8 test stopped after that failure.
This is **not an OOM** and must not be described as a model too large for 16 GB.
The installed Nunchaku loader expects a different quantization layout;
`patch_scale_key` asserts while matching checkpoint state keys.

### BF16 quality diagnostic

One additional 1024 image was generated using the same BF16 file at **28
steps, guidance 3**, seed 42. It completed in **96.74 seconds** client time
(96.21 seconds reported by ComfyUI), with a visibly coherent library image.
This is a single diagnostic observation, not a three-run median, and uses a
different recipe from the eight-step tests. The filename alone does not
establish the BF16 artifact's original model release or distillation status.

## What fits, and what remains unknown

The successful workflows run on the 16 GB card under this dynamic VRAM policy.
They do **not** prove that diffusion weights, text encoder, VAE and activations
are all simultaneously resident in dedicated VRAM. Process RSS and VRAM are
sampled counters; host RAM/staging remains part of the setup. Do not turn this
into a claim that the complete stack needs only the table's VRAM value.

- **Demonstrated runnable:** FP8 Turbo and SDXL Lightning at 512/1024, batch 1;
  BF16 with the separate longer-schedule quality qualification.
- **Compatibility failure:** the existing INT8 artifact with the installed
  Nunchaku Z-Image loader; memory fit remains unknown.
- **Components, not independent models:** Qwen text encoders, AE/Wan VAEs,
  LoRAs, CLIP vision, IPAdapters, InsightFace, RealESRGAN weights and the
  AnimateDiff motion module. The generation benchmarks do not establish their
  behavior in every combined workflow.
- **Video incomplete:** no Wan diffusion base model or matching complete
  AnimateDiff/SD1.5 pipeline was present in the inspected store. No download
  was attempted; no video VRAM claim is made.
- Larger batches/resolutions, alternate encoders, ControlNet and adapter-heavy
  combinations were not tested. No image-quality leaderboard is claimed.

The [existing-file inventory](2026-10-18-comfyui-model-inventory.json) records
relative names, byte sizes and hashes without redistributing weights.
Representative images, original API histories, memory samples and diagnostic
graphs remain in the private article-evidence folder. Public workflow examples
contain only the benchmark prompt and existing relative model filenames.

## Reproduce without downloading models

```bash
python scripts/benchmark_comfyui.py \
  --base-url http://127.0.0.1:8188 \
  --output /path/to/new-benchmark-folder
python scripts/summarize_comfyui.py /path/to/new-benchmark-folder
```

The recorder targets the documented existing filenames. Review the variant
list if your licensed files use other names. It needs the local Illama API
only to unload its model before sharing the B50. The optional Linux telemetry
reader assumes the documented PCI address/container name; adjust those for a
different machine. Keep generated output and raw logs private until reviewed.
For standalone ComfyUI without an Illama service, pass `--skip-illama-unload`
after checking that no competing GPU workload is active. Protected Illama
services use the privately exported `ILLAMA_API_KEY`; the token is not recorded.
